# 产品需求文档（PRD）· Fintech Daily

> 版本：v1（已上线）　|　负责人：aliyabb　|　更新：2026-10

## 1. 背景与机会

金融科技行业信息高度分散：头部媒体、行业通讯、加密媒体、风投研究、各国监管机构，加起来有几十个值得关注的信息源，且以英文为主。非英语市场的从业者获取信息的成本更高。

现有方案的不足：

| 方案 | 问题 |
|---|---|
| 自己订阅几十个源 | 信息过载，同一事件被重复报道，筛选耗时 |
| 人工编辑的日报 | 人力成本高，难以同时覆盖多种语言 |
| 直接用大模型总结 | 存在幻觉风险；金融信息的错误代价很高 |

**机会**：用 AI 流水线替代人工编辑的大部分工作，同时用分层护栏和人工把关保证可信度，以接近零的边际成本服务多个语言市场。

## 2. 目标用户

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 金融科技产品经理、分析师 | 早上通勤时快速了解行业动态 | 3 分钟读完，只看重要的事 |
| 创业者、投资人 | 跟踪融资、并购、监管动向 | 信息准确，附原始出处 |
| 学生、求职者 | 建立行业认知 | 有"为什么重要"的解读 |
| 编辑（内部用户） | 每天审核草稿 | 少操作、能否决、能更正 |

## 3. 产品目标与成功指标

| 目标 | 指标 | 目标值 |
|---|---|---|
| 可信 | 发布前修正率、拦截率；发布后事实更正数 | 所有事实可追溯到原文 |
| 准时 | 准点率 | 100% 在承诺分钟内发出 |
| 稳定 | 发布成功率 | 每天每频道 1 期，不缺刊 |
| 不重复 | 发布后因重复而更正的条目数 | 0 |
| 可持续 | 月运行成本 | $0（免费额度内） |

当前达成情况见 [metrics.md](metrics.md)。

## 4. 功能范围

### v1（已上线）

| 模块 | 功能 |
|---|---|
| 采集 | 54 个 RSS 源，11 个类别，按频道设置来源权重；单个源故障不影响整体 |
| 去重与排序 | 同一事件合并；与近 10 天已发内容比对；按权威性、多源报道、时效打分；单一来源上限 |
| 选题 | 大模型从前 80 条候选中选出 7 条 + 3 条备选，标记重复事件 |
| 写作 | 基于原文全文，输出标题（≤90 字符）、摘要（≤280）、"为什么重要"（≤160）、话题标签、逐字引用 |
| 质量护栏 | 代码校验（数字、日期、来源）→ 跨模型核查（事实、状态、术语、重复）→ 一轮修复 → 仍不通过则删除并由备选补位；少于 3 条则当天不发 |
| 审核 | 草稿与质量报告推送给编辑；auto（否决制）/ manual（批准制）双模式 |
| 发布 | 三个频道按各自时区准点发布：08:30 莫斯科、08:30 新加坡、07:30 UTC |
| 一周回顾 | 每周一在日报前发布，按要闻、交易、监管、趋势分栏，每行链接回原帖 |
| 运营工具 | 发布后删除某条新闻并重新编号、修改话题标签、删除帖子、编辑置顶帖 |

### v2（已上线）

| 模块 | 功能 |
|---|---|
| 运行指标 | `metrics`：准点率、护栏拦截、降级、请求与 token、按官方价估算的单帖成本；旧草稿从质量报告中回溯 |
| 提示词评测 | `eval` 离线检查（0 次请求）；`eval-live` 盲评 A/B，独立 API key 与配额 |
| 「✏️ 重写」 | 编辑用一句话提出修改；只能使用原有来源；改动条目重新过全部护栏，未通过则保留原文；每期最多 2 次 |
| 成本记录 | 每次请求的结果与 token（含 thinking token），按模型、按步骤汇总到每期草稿 |

### 有意不做

| 功能 | 原因 |
|---|---|
| 长文深度解读 | 短条目已有约 15% 需要在发布前修正，长文的幻觉风险与核查成本过高 |
| 实时推送 | 以"每日一读"为核心体验；实时性会显著增加成本与噪声 |
| 自动抓取社交平台 | 平台条款与噪声过滤成本高，当前收益不足 |

## 5. 关键约束

- **零预算**：只使用免费额度（Gemini 免费层、GitHub Actions、免费调度服务）
- **模型不稳定**：免费层高峰期频繁过载，需要降级与重试策略，且质量不能依赖单一模型
- **无服务器**：所有状态以文件形式保存在 git 分支中，每次运行可重复、幂等
- **安全**：只抓取和发布 http/https 链接；密钥仅存于 GitHub Secrets，日志中自动脱敏

## 6. 风险与应对

| 风险 | 应对 |
|---|---|
| 幻觉、事实错误 | 四层护栏：原文依据、代码校验、跨模型核查、人工否决 |
| 重复报道同一事件 | 代码层标题比对 + 选题模型参考发布记忆 + 核查模型二次检查 |
| 模型过载导致质量下降 | 选题环节等待主模型；其余环节降级并由护栏兜底；备选新闻补位 |
| 定时任务延迟 | 外部调度器分钟级唤醒；所有运行幂等 |
| 免费额度耗尽 | 按步骤分配模型；限制重试次数；监控 Actions 用量 |
