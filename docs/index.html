关键产品决策 Decisions

1

用数据决定模型路由

复查发现新的重复新闻全部来自过载时由轻量模型选题的日子 → 只在选题环节等待主模型，其余环节降级、由护栏兜底，并增加二次重复检查。上线 3 天拦截 5 条重复。

2

准时是产品承诺

频道写着 08:30，实际约 08:43 → 外部调度器分钟级唤醒、所有运行幂等。决策前核算免费额度，并清理每月约 330 分钟的冗余任务。延迟 11.8 → 0 分钟。

3

给 AI 自主权，保留人的否决权

auto（否决制）/ manual（批准制）双模式，20 分钟否决窗口；「重写」按钮只能使用原有来源，改动重新过全部护栏，没通过就保留原文。

4

上线不是终点

测试通过后仍在一周后复查全部帖子，发现测试无法覆盖的新根因。在 LLM 系统中，"测试通过"不等于"线上正常"。

Fintech news is scattered across dozens of outlets, newsletters and regulators, mostly in English. A human-edited daily in three languages is expensive. Letting an LLM write finance news is risky: one wrong amount, or "pending" written as "approved", and readers stop trusting the channel.

Key product decisions Decisions

1

Route models by data, not by instinct

An audit showed every new repeat came on days a lightweight fallback model did the selection → wait for the main model only at selection; other steps fall back and guardrails hold quality; a second repeat check added. 5 repeats caught in 3 days.

2

On time is a product promise

The channel said 08:30, posts went out around 08:43 → an external scheduler wakes the bot on the minute; every run is idempotent. Budgeted the free tier first and removed ~330 wasted minutes a month. Delay 11.8 → 0 min.

3

Autonomy for the AI, a veto for the human

Auto (veto) and manual (approve) modes with a 20-minute veto window. "Rewrite" may only use the original sources and re-runs every guardrail; an edit that fails keeps the old text.

4

Launch is not the finish line

A week after a fix that passed its tests, every post was audited again and a new root cause surfaced. In LLM systems, passing tests is not the same as working in production.
