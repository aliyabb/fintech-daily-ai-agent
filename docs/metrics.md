# 指标定义与计算方法

> 统计区间：2026-09-25 至 2026-10-09，3 个频道 × 15 天 = 45 期日报。
> 数据来源：机器人为每期保存的草稿记录（发布时间、使用的模型、质量报告、最终内容），保留最近 14 天。
> 计算方式：`python -m newsbot metrics`（运行指标）与 `python -m newsbot eval`（离线评测）自动生成，下表即其输出。

## 原则

1. **只公布能从运行数据中算出的数字。** 尚未测量的指标标注"待上线"，不做估计。
2. **每个指标都写清分子和分母**，方便复核。
3. **区分 AI 质量、可靠性、成本、业务四类指标**，避免只看模型效果而忽视产品结果。

## AI 质量

| 指标 | 定义 | 数值 |
|---|---|---|
| 生成条目数 | 最终发布的条目 + 被护栏删除的条目（不含模型未写出的 1 条） | 306（301 + 5） |
| 发布前修正率 | 被修复环节修改过的条目 / 生成条目 | **15.0%**（46 / 306） |
| 拦截率 | 修复后仍不通过而被删除的条目 / 生成条目 | **1.6%**（5 / 306） |
| 代码校验占比 | 由确定性代码发现的问题 / 全部被修正的问题 | **74%**（34 / 46） |
| 重复拦截数 | 核查环节标记为重复并删除的条目 | **5**（第二道重复检查上线后 3 天） |

**46 次修正的来源分布：**

| 发现者 | 问题类型 | 次数 |
|---|---|---|
| 代码校验 | 引用了不属于本条新闻的来源 | 22 |
| 代码校验 | 数字或日期在原文引用中找不到 | 12 |
| 核查模型 | 事实、状态、术语翻译错误 | 12 |

**解读**：确定性校验几乎零成本，却发现了约四分之三的问题；核查模型负责发现语义层面的细微错误，例如"支持"与"发行"、"不含"与"扣除后"的混淆。

## 模型可用性

免费层高峰期，主模型经常返回"过载"（HTTP 503）。机器人会按配置依次尝试备用模型。

| 指标 | 定义 | 数值 |
|---|---|---|
| 降级率 | 至少一个环节由 Flash Lite 完成的期次 / 全部期次 | 100%（45 / 45） |
| 选题降级率 | 选题由 Flash Lite 完成的期次 / 全部期次 | 64%（29 / 45） |
| 选题降级率（调整前） | 选题由 Flash Lite 完成的期次，09-25 至 10-06 | 67%（24 / 36） |
| 选题降级率（调整后） | 同上，10-07 至 10-09 | 56%（5 / 9），样本仍小 |

**解读**：模型可用性不受产品控制，因此质量保障设计成与模型无关：无论哪个模型生成，都要经过同样的代码校验和核查。

## 可靠性

| 指标 | 定义 | 数值 |
|---|---|---|
| 发布成功率 | 发出的期次 / 计划期次 | **100%**（45 / 45） |
| 首次构建成功率 | 第一次尝试即生成草稿的期次 | 98%（44 / 45），另 1 期在自动重试后成功 |
| 准点率（方案上线后） | 在承诺分钟内发出的期次，09-29 至 10-09 | **100%**（33 / 33） |
| 平均延迟（方案上线前） | 实际发布时间 − 承诺时间，09-25 至 09-28 | 11.8 分钟（最长 13.4 分钟） |
| 信息源故障 | 每次采集中抓取失败的信息源数量 | 统计期内为 0 |

## 离线评测（`eval`，0 次模型请求）

对统计期内 45 期、301 条已发布条目做确定性检查：

| 检查 | 通过 |
|---|---|
| 标题 ≤ 90、摘要 ≤ 280、"为什么重要" ≤ 160 字符（提示词中的限制） | 295 / 301（98%） |
| 文字使用频道语言 | 301 / 301（100%） |
| 无感叹号与表情 | 301 / 301（100%） |
| 1–3 个来源，均为 http(s) | 301 / 301（100%） |
| 话题标签均在频道词表内 | 45 / 45 期（100%） |
| 同一帖内没有两条讲同一事件 | 45 / 45 期（100%） |

**发现**：6 条超出长度限制 1–14 个字符。代码只在更宽松的上限处截断，模型并不总是严格遵守提示词里的字数要求。

## 在线评测（`eval-live`）

当前提示词重写最近 3 期，另一个模型盲评"已发布版本"与"新版本"，四个维度 1–5 分：

| 维度 | 含义 |
|---|---|
| accuracy 准确性 | 所有事实都能在来源中找到；出现无依据的事实最高 2 分 |
| tone 语气 | 冷静、分析性，无夸张、无投资建议 |
| why_value "为什么重要"的价值 | 对受众具体、有用，而不是"这对行业很重要"这类套话 |
| clarity 清晰度 | 忙碌的从业者读一遍就能理解 |

每次约 4 个请求（写作模型漏写时多 1 个补写请求），使用独立的 API key 和配额。结果保存在运行记录中，每次与上一次对比。

### 免费额度用量（v2 上线后，2026-10-10 至 10-12，9 期每日简报）

免费层按模型限制每分钟和每天的请求次数，所以要知道每期用掉多少额度、花在哪个环节。

| 指标 | 数值 |
|---|---|
| 每期模型请求 | 平均 8.4 次，其中 51% 为失败请求（主要是高峰期"过载"），失败请求同样计入配额 |
| 每期 token | 平均约 5.8 万（输入约 4.4 万，输出约 1.3 万） |
| 请求最多的环节 | 事实核查：31 / 76 次请求，输入 token 也最多，因为要带上原文 |

样本只有 9 期，数字随每周指标快照持续更新。

## 周度快照

每周一定时任务自动运行 `metrics`，把最近 7 天的指标保存为一份快照，并在报告末尾生成周度趋势表（最近 12 周）。草稿只保留 14 天，快照长期保留，因此可以比较不同周的准点率、修正率、降级率与免费额度用量。

## 模型变更

3.7 Flash 已于 2026-10-09 下线并被重定向到 3.8 Flash。随后在配置中把选题与核查切换到 3.6 Flash，保持"写作与核查由不同模型完成"，并让两类环节继续使用各自的免费额度。

## 局限

- 草稿只保留 14 天，因此统计区间不包含上线首周；自 2026-10-12 起每周快照长期保留。
- "修正率"统计的是**发布前被发现并修正**的问题，不等于发布后的错误率。
- 降级率调整后的样本只有 9 期，结论需要更长时间验证。
